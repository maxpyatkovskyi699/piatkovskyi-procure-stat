# Інструкція з внеску в проєкт (Contributing Guidelines)

Дякуємо за ваш внесок у розвиток проєкту! Будь ласка, дотримуйтесь наведених нижче правил.

## 1. Іменування гілок

Назви гілок мають починатися з відповідного префіксу та описувати суть змін:

- `feature/назва-фічі` — додавання нового функціоналу (наприклад, `feature/title-normalizer`).
- `fix/назва-багу` — виправлення помилок.
- `docs/опис-змін` — оновлення документації.

## 2. Формат повідомлень комітів

Використовуйте стандарт Conventional Commits:

- `feat: ...` — додавання нової функції.
- `fix: ...` — виправлення помилки.
- `docs: ...` — зміни у документації.
- `refactor: ...` — рефакторинг коду без зміни функціоналу.

Повідомлення мають бути лаконічними та згадувати контекст змін.

## 3. Вимоги до Pull Request (PR)

- PR повинен створюватися з тематичної гілки у гілку `main`.
- В описі PR обов'язково вказуйте посилання на Issue, яке закривається (наприклад, `Closes #1`).
- Перед створенням PR переконайтеся, що код пройшов перевірку лінтером (`ruff check .`).
- Кожен PR має отримати щонайменше 1 успішне код-рев'ю перед злиттям.
