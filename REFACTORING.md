# Журнал рефакторингу (Refactoring Log)

## Обробка нечислових та відсутніх сум закупівель (`amount`)

### Опис зміни

Логіку перетворення та нормалізації сирого словника в доменну модель винесено в окремий модуль `src/domain/parsing.py`. Функція `parse_amount` перевіряє та кастує суму закупівлі.

### Зміна поведінки (Breaking Change)

- **Застаріла поведінка (Legacy):** У разі нечислового значення суми (наприклад, `"за домовленістю"`, `"невідомо"`) або її відсутності функція повертала `0`.
- **Нова поведінка:** Замість `0` повертається `None`.

### Обґрунтування

Зміна є свідомим рішенням для підвищення точності предметної області:

- **`0`** позначає безкоштовну/нульову закупівлю.
- **`None`** позначає стан, коли бюджет закупівлі невідомий або не вказаний.

Об'єднання цих двох станів створювало спотворення даних. Зміна відображена в тип-аннотації `Procurement.amount: int | None`.

### Оновлення тестів

Характеризаційний тест у `tests/test_characterization.py` оновлено під нову поведінку: некоректні значення суми тепер повертають None замість 0.
Тестові модулі `tests/test_loader.py` та `tests/test_none_loader.py` актуалізовано для перевірки корректності парсингу, дедуплікації та фільтрації полів.

### Збереження порядку елементів при дедуплікації

- Оскільки доменна модель `Procurement` є незмінною (`frozen=True`), дедуплікацію можна було б виконати в один рядок через `set(items)`.
- Використання `set(items)` призводить до втрати початкового порядку записів у потоці.
- **Прийняте рішення:** Функція `deduplicate()` реалізована через генератор із використанням допоміжної множини `seen`. Це дозволяє:
  1. Зберегти оригінальний порядок першого входження елементів.
  2. Забезпечити «ледачу» (lazy) обробку даних без завантаження всієї колекції в пам'ять одразу.
